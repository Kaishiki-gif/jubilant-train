# LINE 韻トレーニングBot セットアップガイド

ラップの「韻」を練習するためのLINE Botです。毎朝9時(日本時間)に、友だち登録した一人ひとりへ個別に「お題」の単語を送ります。ユーザーがそれに韻を踏む単語を返すと、母音が一致しているかBotが判定してくれます。

## ゲームの流れ

1. Botが「お題」の単語を送る(例: 「愛(あい) / 母音: ai」)。
2. ユーザーが韻を踏むつもりの単語を1つずつ送る。
3. Botが単語の読みを推定し、母音だけを取り出して判定。
   - **○**: お題の母音と完全一致 → カウント+1、結果リストに追加。次の単語を促す。
   - **△**: お題の母音を半分に割った「後半部分」とユーザーの単語の母音が一致 → カウントは増えないが結果リストには追加。
   - **×**: 一致しない → カウントなし、リストにも追加しない。
4. ○が4つ貯まったらそのラウンド終了、結果リストを表示。
5. リッチメニューの「お題を受け取る」ボタンをタップすると、いつでも自分だけ新しいお題を受け取り直せる(9時の自動配信とは別に何度でも遊べる)。

### 母音の取り出し方(仕様)

「伸ばし棒(ー)」「ん」「小さい文字(っ、ゃゅょ、ぁぃぅぇぉ)」は母音バージョンから除外する、という指定に沿って実装しています。例えば「きゃく」→ 母音は `iu`(きの"i"、くの"u"。ゃは除外されるため"a"は含まれません)。これは音声学的な母音とは異なりますが、指定された仕様どおりの挙動です。

△判定の「後半一致」は、お題の母音文字列を半分に割った後半部分と、ユーザーの単語の母音文字列(全体)が一致するかで判定しています(例: お題「愛」の母音"ai"の後半は"i" → ユーザーの単語の母音が"i"だけなら△)。この解釈で問題があれば `kana.js` の `judge()` を調整してください。

### 単語の読み方推定について

ユーザーが漢字で単語を送っても読めるように、`kuromoji`という形態素解析ライブラリで自動的に読み(ふりがな)を推定しています。ただし辞書ベースの推定なので、固有名詞や辞書にない単語は読み間違いが起きることがあります。判定に納得がいかない場合は、ひらがなで送り直すよう伝えてください。

## ファイル構成

```
webhook-server/
  index.js          サーバー本体(Webhook受信・毎日9時の自動配信・韻判定ロジック)
  kana.js            母音抽出・音数カウント・韻判定ロジック(単体でテスト可能)
  theme-words.json  お題単語データ(2〜8音、89語。word/reading/vowelsを保持)
  curate_words.js   theme-words.json を生成したスクリプト(単語を追加したいときに編集して再実行)
  package.json
  .env.example      環境変数のサンプル
  users.json         友だち登録したuserIdの保存先(自動生成・自動更新)
  sessions.json      各ユーザーの進行中セッション(お題・カウント・結果リスト、自動生成)
  daily-state.json  毎日のお題ローテーション状態(自動生成)
  richmenu.png       リッチメニュー画像
  make_richmenu.py  リッチメニュー画像を作ったPythonスクリプト
```

以前のバージョン(日本語単語の意味・例文を届けるBot)で使っていた `words.json` は現在未使用です。削除しても問題ありません。

## 手順1: LINE公式アカウント/チャネルを作る

1. [LINE Official Account Manager](https://manager.line.biz/) にLINEアカウントでログインし、公式アカウントを新規作成する。
2. 作成した公式アカウントの管理画面右上「設定」→左メニュー「Messaging API」を開き、「Messaging APIを利用する」を選択してプロバイダーを指定・同意する。
3. 同じアカウントで [LINE Developers コンソール](https://developers.line.biz/console/) にログインし、チャネルが作成されていることを確認する。
4. チャネルの「Messaging API設定」タブで以下を控える。
   - チャネルアクセストークン(長期): 「発行」ボタンから発行
   - チャネルシークレット: 「チャネル基本設定」タブに表示
5. 同じ画面で「応答メッセージ」をオフ、「Webhookの利用」を後で有効にできるようにしておく(手順3でURLを設定してから有効化)。

## 手順2: サーバーをデプロイする(例: Render)

Render以外でも動きますが、無料枠があり手順が簡単なため一例として案内します。

1. `webhook-server` フォルダをGitHubリポジトリにアップロードする。
2. [Render](https://render.com/) で「New +」→「Web Service」→ 該当リポジトリを選択。
3. Build Command: `npm install` / Start Command: `npm start` を設定。
4. 環境変数(Environment)に以下を設定する。
   - `LINE_CHANNEL_ACCESS_TOKEN`: 手順1で発行したトークン
   - `LINE_CHANNEL_SECRET`: 手順1で確認したシークレット
   - `USERS_API_SECRET`: 好きなランダム文字列(動作確認用エンドポイントの保護に使う)
5. デプロイが完了すると `https://<サービス名>.onrender.com` のようなURLが発行される。

**注意:** Renderの無料プランは一定時間アクセスがないとスリープします。9:00の自動送信タイミングでスリープしていると`node-cron`のタイマー自体が止まってしまうため、無料運用する場合は外部の死活監視サービス(UptimeRobotなど)で数分おきに `/` にアクセスさせ、スリープさせない工夫を推奨します。予算が許せば有料プラン(常時起動)にするのが確実です。

## 手順3: Webhook URLをLINE側に設定する

1. LINE Developersコンソールのチャネル→「Messaging API設定」タブを開く。
2. 「Webhook URL」に `https://<サービス名>.onrender.com/webhook` を入力して保存。
3. 「Webhookの利用」をオンにする。
4. 「検証」ボタンを押し、200 OKが返ることを確認する。

## 手順4: リッチメニューを設置する

デプロイ後に一度だけ、以下のURLにブラウザでアクセスしてください(トークンは `USERS_API_SECRET` の値)。

```
https://<サービス名>.onrender.com/setup-richmenu?token=<USERS_API_SECRET>
```

これでトーク画面下部に「お題を受け取る」ボタンが表示されます。コードを更新して再実行しても、古いメニューを削除してから作り直すので増殖しません。

## 手順5: 友だち追加してテストする

1. Messaging API設定タブにあるQRコードを読み取り、Botを友だち追加する。
2. 案内メッセージが届き、1:1のトークルームができていることを確認する。
3. リッチメニューの「お題を受け取る」をタップすると、その場でお題が届く。
4. お題に韻を踏むつもりの単語を1つ送ってみて、○/△/×判定が返ってくることを確認する。
5. 動作確認用エンドポイントで、9時の一斉配信を即座にテストすることもできます。

```
curl -X POST "https://<サービス名>.onrender.com/send-daily-theme?token=<USERS_API_SECRET>"
```

6. 実際に9:00になれば自動で全登録ユーザーにお題が配信されます(タイムゾーンは Asia/Tokyo)。

## 無料利用時の制限

LINE公式アカウントの無料プラン(コミュニケーションプラン)は、月200通まで無料です。通数は「送信人数 × 1通あたりのバブル数」で計算されるため、例えば10人に毎日1通送ると月300通(10人×30日)となり無料枠を超えます。無料枠内で運用したい場合は、対象者を月200÷30 ≒ 6人程度までにするか、有料プラン(ライトプラン: 月5,000円で5,000通など)への切り替えを検討してください。
